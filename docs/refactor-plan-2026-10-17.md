# rehab-timer 交互与云存储重构方案

日期：2026-10-17。
状态：方案已获批准并进入实施。
本文保留重构前的问题与设计依据，现行实现、部署和验收方法以 README.md、PRODUCT.md 和 docs/sync-api.md 为准。

## 1. 目标与范围

保留两套训练计划、现有训练剂量和声音规则，重构训练中的操作层级，并把正式记录迁入 Cloudflare D1。
一到两个人共享同一本训练记录，不设置账号、用户表、个人统计或权限角色。
两个人的完成次数合并统计，界面明确标为共享记录，不能解释为个人完成次数。
每次训练仍有独立会话，避免两人同时使用时覆盖彼此的进度。
一期不增加计划编辑、实时协作、自动跨设备接管，也不为此次重构引入前端框架。

## 2. 现状与证据

应用的界面、领域逻辑、媒体控制和存储都在 `index.html`，固定音频随 `audio/` 发布。
现有 44 项自动测试已通过，覆盖计时边界、完整流程、媒体控制、恢复、日期和存储失败。
这些测试应成为重构的回归基线，不能因拆分文件而复制一份不同的测试用引擎。

已通过 ego-browser 的独立任务空间检查 390×844 与 375×667 视口，全部交互测试使用隔离存储。
复现了暂停后切到另一个计划再切回直接变为空闲状态，小屏训练操作需要滚动，暂停与继续按钮不在相同位置。
另用代码支持的 `debugMs=20` 完整走完原计划 101 段和四次手动继续，复现“今天先标记再取消，后来训练完成显示已保存，但日历仍未完成且本周次数为 0”。
这轮没有验证真实扬声器输出或手机锁屏行为。

正常声音模式使用连续阶段音轨的位置推动训练状态，加速验证另有单调时钟路径。
首次播放必须同步发生在点击手势内，不能等待云端响应后再调用 `play()`。
恢复只进入暂停或项间就位，不消耗离线时间，也不自动播放。
相关约束见 `index.html:331`、`index.html:392`、`index.html:647` 和 `README.md:25`。

## 3. 交互方向

继续使用 `DESIGN.md` 的水蓝泳道计分板、深色计时区和橙色主要操作，不换成圆环计时器或装饰性仪表盘。
页面按准备、训练、暂停、项间就位和完成组织，减少同一时刻需要判断的按钮数量。
训练中优先呈现完整动作名、器材、当前组次、当前阶段和倒计时，五个进度点保持可见。
手机上的暂停或继续应位于容易触达的位置，结束降为次要操作，并继续要求确认。
跳过只在允许的准备或组间休息出现，不提供跳过工作段的入口。
手工计次阶段明确显示“完成第 1 组”或“完成第 2 组”，第一次完成后等待明确开始第二组，并防止同一次双击跨组提交。
这只增加就位确认，不增加训练剂量或固定休息时长。

切换计划时提供保留当前暂停进度或明确结束的选择，不再把普通标签切换当作清空命令。
标签方向键只移动焦点，Enter 或 Space 才选择计划。
刷新优先呈现本设备最近计划及可恢复训练，其他设备的云端会话不会被自动接管。
声音状态与试听或重试放在同一区域，网络状态不挤占计时主视觉。
完成页分别展示“训练已完成”和“记录已同步”或“等待同步”，不把两种成功混为一谈。
日历点击日期后展开当天记录和补记入口，取消操作明确指向选中的记录。
保留完整中文、键盘焦点、至少 44px 触控区域和 reduced-motion，验收覆盖 320px 窄屏。

## 4. 推荐架构

保留现有 Cloudflare Pages 项目与域名，增加同源 Pages Functions API，并绑定 D1。
浏览器只调用同源 API，不接触数据库凭据或 Cloudflare 管理令牌。
页面、训练领域、媒体适配、同步存储和日历投影按职责拆分，使修改边界清楚。
建议源代码使用原生 JavaScript 模块加 JSDoc，通过轻量构建输出可由普通 script 加载的 IIFE 资源，保留无需本地服务器的文件预览。
不直接把浏览器 ES 模块和网络 API 放入 `file://` 验收路径；该路径使用隔离存储适配器，云接口在 Pages 分支预览验收。
计时引擎和媒体行为先保持语义一致，再由回归测试保护后续整理。

建议设置一个共享访问口令，两个使用者使用同一入口，不建立账号系统。
口令由服务端验证，敏感配置仅存在 Cloudflare 服务端环境，不能写入前端代码或公开仓库。
验证后使用安全会话 Cookie，读取历史和写入记录都经过服务端访问检查。
服务端同时校验来源、输入尺寸、计划标识和允许状态，口令验证增加失败频率限制。

## 5. 数据模型与日历语义

| 表 | 职责与主要字段 |
| --- | --- |
| `sessions` | 每场训练一行，保存 `session_id`、`program_id`、`status`、快照、`revision`、`writer_epoch`、完成日期和完成时间。 |
| `calendar_adjustments` | 保存手工补记、撤销及明确目标记录 ID，使用独立操作 ID 保证重试不重复。 |
| `legacy_imports` | 保存导入批次、原始覆盖值、来源摘要、映射和冲突结果，供迁移核对。 |

完成与放弃都是会话终态，迟到的进度请求不能把它们恢复成进行中。
同一会话的首次完成结果不可被重试改写，完成日期保留设备当时的本地日历日期，同时保存 ISO 完成时间。
新记录同时保存完成设备的时区，查看设备改变时区不会重新分配历史日期；旧数据缺失的时区标为未知，不推测补全。
同日不同会话仍计多次，月历按当天是否存在有效记录点亮。
周统计保持当地周一至周日，两套计划独立计算。

修正现有“取消整天后永久遮住未来完成”的语义。
取消只撤销操作时明确选中的会话或补记，不物理删除原始训练记录。
此后同一天完成的新会话仍然点亮日期并计入统计。
补记和真实训练分别标识，避免用虚构完成时间把补记伪装成完整训练。

## 6. 同步与单一写入权

D1 是正式数据源，本地只保留恢复快照和待同步队列，支持短暂断网与页面重开。
训练运行不等待网络，云快照每 10 秒合并一次，暂停、阶段边界、完成和结束立即进入同步队列。
同一会话请求串行发送，并以 `revision` 拒绝过期写入。
完成先保留本地终态意图，再请求云端幂等确认，确认后才能显示“已同步”。
断网显示等待同步，失败允许重试，页面关闭时的请求只作补充保障。

另一个设备不能自动恢复云端最新会话。
使用者必须明确选择一个暂停快照，并在线取得单一写入权后继续。
接管增加 `writer_epoch` 并签发写入令牌，服务器拒绝旧令牌继续修改该会话。
旧终端在下一次同步发现失效后停止同步并提示，不自动覆盖新终端的数据。
无法即时通知的离线旧端保留待处理内容，联网后显示冲突，不能把冲突当作同步成功。
失去写入权后不得自动换令牌重发或丢弃待同步数据。
若旧端实际完成训练，由使用者明确选择保留云端结果，或将本地完成另存为新的独立会话，并提示后一操作会增加一次共享完成次数。
离线只允许当前已经持有的会话继续，不允许接管其他设备会话。

API 以读取共享状态、创建会话、保存快照、完成、结束、修改日历和迁移导入为边界。
完成与进度清理在一个数据库事务内处理，写入权、版本和终态检查由服务端执行。
返回前台时刷新共享日历，一期无需持续广播或实时双向控制。

## 7. 旧数据迁移

原计划键为 `rehab-timer:v1:progress`、`rehab-timer:v1:done:<id>` 和 `rehab-timer:v1:date:<date>`。
新计划在 `rehab-timer:v1` 后增加 `:joint`，测试数据使用独立的 `rehab-timer:test:v1:<unit-ms>` 前缀。
迁移仅扫描正式前缀，逐条校验版本、会话 ID、日期和快照状态。
不能调用 `Store.history()` 导出，因为被取消日期的原始记录已被隐藏，补记也已被合成。

首次展示迁移预览，列出两套计划的完成记录、手工修改、未结束训练和异常数量。
完成记录保留原 ID，重复导入幂等，同一天不同 ID 不合并。
旧 `true` 覆盖按原效果转为明确的补记记录，已经存在有效会话时不额外增加次数。
旧 `false` 覆盖只取消本批次中该日期对应的目标记录 ID，不影响云端既有记录和未来新会话。
自动取消仅作用于该批次新插入的记录；目标 ID 已在云端时列为冲突，不能自动改变有效状态。
补记和撤销使用由导入来源、旧键及内容生成的稳定操作 ID，重复导入复用同一操作，不能重复生成调整记录。
原始覆盖值保存在 `legacy_imports`，冲突展示核对，不能按导入时间决定谁覆盖谁。
损坏数据保留并报告，成功导入后也不自动删除旧键。

旧数据受浏览器和来源隔离，必须在原正式域名、原浏览器中读取。
其他设备需要分别导入，不能承诺服务器能直接取出手机中的本地历史。

## 8. 环境与发布

生产和分支预览绑定不同 D1，凭据、数据库迁移和访问配置分别管理。
正式页面的 `test=1` 与加速模式继续使用隔离测试适配器，不允许写入生产数据库。
云端端到端验收使用预览环境和合成数据，测试参数不能成为访问生产数据的旁路。

当前 Pages 使用直接上传，Git 合并不等于线上发布，现有步骤见 `README.md:96`。
实施时需要把 Functions、静态模块和数据库迁移加入发布流程，音频仍随页面共同发布。
上线顺序为兼容的数据表和 API、预览验收、正式页面发布、正式来源只读核对。
保留前一版静态资源和后端兼容接口，回滚不能删除已迁入的云记录。

## 9. 实施顺序与验收

第一阶段完成状态页面与交互原型，确认手机操作顺序和日期记录语义。
第二阶段拆分模块并保留现有 44 项测试，逐项证明正常音轨和 debug 路径没有改变训练规则。
第三阶段加入 API、D1、本地队列、访问口令与单一写入权，使用合成数据验证。
第四阶段完成迁移预览、冲突处理和分支预览验收，再安排生产发布。

必须覆盖两端同时练不同会话、同会话接管、旧终端重连、过期快照和结束后的迟到请求。
必须覆盖完成请求超时重试、断网完成后刷新补传、午夜完成次日上传和重复导入。
日历必须验证取消旧记录后同日新增仍点亮，补记次数正确，跨设备迁移冲突可见。
界面必须验证暂停继续、项间人工确认、长动作名、声音手势、窄屏触控和无横向溢出。
所有浏览器步骤仅用 ego-browser，手机锁屏和实际听音仍由目标设备实测，不能以媒体事件代替。
方案已获批准，执行情况与验证证据将在实施 PR 中记录。

## 10. 官方依据

以下文档已于本次调研通过 ego-browser 核对。
Pages Functions 支持绑定 D1，生产与预览环境可以分别配置绑定。

[Pages Functions 资源绑定](https://developers.cloudflare.com/pages/functions/bindings/)

[Pages 直接上传](https://developers.cloudflare.com/pages/get-started/direct-upload/)

D1 的 batch 支持 SQL 事务，语句失败会回滚批次。
版本冲突不一定表现为 SQL 异常，条件更新影响行数为零仍须由应用明确处理，不能把 batch 当成自动解决业务竞争。

[D1 数据库 API](https://developers.cloudflare.com/d1/worker-api/d1-database/)
