# 康复训练计时器

现有线上入口：<https://rehab-timer.pages.dev/>。
自包含的 `index.html`，无构建步骤、框架、运行时网络依赖、登录或后端。
训练方案以 [PRODUCT.md](PRODUCT.md) 为准，视觉规则见 [DESIGN.md](DESIGN.md)。

## 使用

- 首次点击开始，有 30 秒准备，可跳过准备。
- 前四项各训练 15 秒 / 重复间休息 5 秒，6 次 × 2 组；组间休息 60 秒，可「跳过休息」。
- 每项第 1 组末次直接组休，第 2 组末次直接完成，不多加短休。
- 第五项为踮脚 30 秒 → 拉伸 30 秒，共 4 轮，无插入休息。
- 前四项完成后，必须点击「准备好了，开始下一项」，不会自动开始下一项。
- 可暂停和继续当前段；结束须确认，仅清当前进度，不删除历史。
- 第五项第四轮拉伸结束才自动完整打卡。

保持手机解锁、页面前台和媒体音量。
离开前台会暂停，回来后需手动继续。
语音或常亮能力不可用时有明确警告，计时不会无限等候语音。
浏览器的语音事件不代表扬声器确实可听，设备静音、语音资源和锁屏限制须在实际设备上检查。

## 本地数据

正式来源使用 `rehab-timer:v1:progress` 保存未完成进度，使用 `rehab-timer:v1:done:<session-id>` 保存完整会话。
同一会话重复回调或重试不会重复打卡；同日不同完整会话计多次，日历只标记一次日期。
按最后完成时的本地日期打卡，跨午夜按完成日；周统计为当地周一至周日，展示每周 3-4 次原有频率，不设连续天数目标。
刷新或重开后进度只恢复为暂停或就位，不消耗离线时间。
写入失败会提示未保存并允许重试，损坏/不兼容数据不会被当作完整训练。

数据仅在同一浏览器、设备、来源保留，不云同步，清除网站数据可能丢失。
预览域名、正式域名和本地文件的存储不共享；`file://` 存储是否持久、是否按文件隔离取决于浏览器。
不要在验证过程中删除真实网站数据。

## 自动测试

需要已有 Node.js 20 或更新版本，无需安装依赖：

```sh
node --test tests/rehab.test.cjs
git diff --check
```

测试直接执行 `index.html` 中的领域代码，并解析页面脚本的语法，不复制另一份计时实现。
覆盖实际完整执行的 101 段顺序与时长、四个手动等待边界、组休跳过、暂停/继续、晚回调、重置、第五项八段连续交替、完整打卡、幂等写入、本地跨日/跨周/月历、恢复及存储失败。
语音适配器的确定性测试覆盖正常 start/end 交接、强引用、取消旧回调、即时假 end、失败和超时。
GitHub Actions 的 `验证` 工作流运行同一测试命令，不承担部署。

## 浏览器验收

只使用 ego-browser 的一个自有任务空间，通过 `file://` 或同一 Pages 项目的分支预览测试。
不启动本地服务器，不使用其他浏览器自动化栈。

- `index.html?debugMs=100`：1 秒按 100 毫秒执行，约 143 秒计时加四次人工等待；关闭语音，仅用短提示音和独立测试存储。
- `index.html?test=1`：保持标准秒长、中文语音与提示音，但所有进度和打卡仍写测试存储。
- 无参数：正式时长与正式本地数据；自动验收仅检查默认配置，不启动会产生正式记录的测试会话。

测试存储前缀为 `rehab-timer:test:v1:<unit-ms>`，刷新可保留测试打卡，绝不混入正式数据。
不要把加速段当作语音效果测试；加速后的 5 秒短休无法容纳正常中文播报。
`window.__rehabTimer` 仅提供状态、计划与有界诊断事件，没有跳项或强制完成接口。

完整浏览器验收应依次确认：

1. 全部五项走完，四个项间边界经过等待仍不自动开始。
2. 组休点击「跳过休息」只进入当前项第二组，工作/短休无跳过按钮。
3. 第五项四轮共八段，自动交替、连续零点，无额外休息。
4. 完成后刷新仍有一条测试记录，正式存储内容不变。
5. 部分训练暂停、刷新恢复、明确继续、确认结束，不新增打卡或删除历史。
6. 实时测试检查初始 30 秒、15 秒工作以及至少一次真实 API 语音/提示音交接，记录系统是否有正常 start/end，单独说明是否人耳验证。
7. 桌面和手机同轮检查完整长动作名、五点、焦点、对比、触控、翻月和 reduced-motion；批量修正后最多一次视觉确认。

私有证据放在当前任务的私有目录，不提交真实健康历史或个人临床记录。
