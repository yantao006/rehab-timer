# 康复训练计时器

现有线上入口：<https://rehab-timer.pages.dev/>。
`index.html` 内含界面和逻辑，`audio/` 内含随站提供的短语音与提示音。
无构建步骤、框架、外部运行时服务、登录或后端。
两套训练方案以 [PRODUCT.md](PRODUCT.md) 为准，视觉规则见 [DESIGN.md](DESIGN.md)。

## 使用

- 用「原计划」或「下肢关节居家训练」标签选择训练；切换会停掉尚未结束的一次训练，不产生完成记录。
- 两套计划首次点击开始都有 30 秒准备，可跳过准备。
- 以下原计划的计时和完成逻辑不变。
- 前四项各训练 15 秒 / 重复间休息 5 秒，6 次 × 2 组；组间休息 60 秒，可「跳过休息」。
- 每项第 1 组末次直接组休，第 2 组末次直接完成，不多加短休。
- 第五项为踮脚 30 秒 → 拉伸 30 秒，共 4 轮，无插入休息。
- 前四项完成后，必须点击「准备好了，开始下一项」，不会自动开始下一项。
- 可暂停和继续当前段；结束须确认，仅清当前进度，不删除历史。
- 第五项第四轮拉伸结束才自动完整打卡。

新计划的前四节各为 15 秒训练、5 秒休息、6 次 × 2 组。
同一节两组之间只有第 1 组最后一次后的 5 秒休息，没有 60 秒组间休息。
每节结束后另休息 60 秒，包含第 4 节完成后到第 5 节之前；休息结束仍要点击「准备好了，开始下一项」。
第 5 节「双侧抬腿跨障碍」每组 8 到 10 次、不计时，两组分别点击「完成」；第二次点击后才记录整套完成。

首次开始或继续时请保持页面有用户手势并打开媒体音量。
训练项内使用一条连续本地音轨承载语音和提示音，页面隐藏后不依赖 visibilitychange 回调，桌面浏览器通常可继续播放。
手机锁屏、系统省电策略、静音开关、蓝牙路由和浏览器后台策略可能停止或延迟媒体；浏览器没有保证 iOS 锁屏后台网页持续运行的通用能力。
若音轨被系统中断，回来后页面会保守暂停，需手动继续；项间仍需手动确认。
「试听声音」播放本地样本，声音异常时同一位置显示短状态与「重试声音」。
声音关时继续视觉计时；重新开启或试听会先暂停当前训练，之后手动继续。
首次开始、继续及重试都在点击手势内直接调用同一个媒体元素的 `play()`，不先等待其他音频 API。
不依赖 `speechSynthesis`、设备中文 voice 或纯 Web Audio 输出；支持 AudioSession 时只使用 `playback` 类型。
素材预加载到页面内存，失败时原资源仍可通过原生媒体加载重试，不写入本地历史。
语音与提示音不并行、不排队；播放拒绝、资源错误、假结束、超时和超界中断均短提示，并保留视觉计时及手动恢复操作。
素材来源、许可和生成方法见 [audio/README.md](audio/README.md)。
浏览器媒体解码进度不代表扬声器确实可听；iPhone 浏览器/iOS 版本、静音开关、媒体音量、蓝牙路由和实际听音仍须目标设备确认。

## 本地数据

原计划沿用正式来源的 `rehab-timer:v1:progress` 保存未完成进度，以及 `rehab-timer:v1:done:<session-id>` 保存完整会话，原有历史不迁移、不删除。
新计划使用 `rehab-timer:v1:joint:progress`、`rehab-timer:v1:joint:done:<session-id>` 和 `rehab-timer:v1:joint:date:<yyyy-mm-dd>`；两套日历、周统计和日期编辑互相隔离。
原计划手动日期编辑仍使用 `rehab-timer:v1:date:<yyyy-mm-dd>` 保存布尔覆盖值，可为过去或今天补记，也可取消日期标记，不删除原始会话键。
同一会话重复回调或重试不会重复打卡；同日不同完整会话计多次，日历只标记一次日期。
按最后完成时的本地日期打卡，跨午夜按完成日；周统计为当地周一至周日，展示每周 3-4 次原有频率，不设连续天数目标。
刷新或重开后进度只恢复为暂停或就位，不消耗离线时间。
写入失败会提示未保存并允许重试，损坏/不兼容数据不会被当作完整训练。

数据仅在同一浏览器、设备、来源保留，不云同步，清除网站数据可能丢失。
预览域名、正式域名和本地文件的存储不共享；`file://` 存储是否持久、是否按文件隔离取决于浏览器。
不要在验证过程中删除真实网站数据。

## 自动测试

需要已有 Node.js 20 或更新版本，无需安装依赖：

```sh
node --test tests/rehab.test.cjs
git diff --check
```

测试直接执行 `index.html` 中的领域代码，并解析页面脚本的语法，不复制另一份计时实现。
覆盖实际完整执行的 101 段顺序与时长、四个手动等待边界、组休跳过、暂停/继续、晚回调、重置、第五项八段连续交替、完整打卡、幂等写入、本地跨日/跨周/月历、恢复及存储失败。
媒体适配器与实际页面控制器的确定性测试覆盖同步手势启动、连续阶段音轨边界、页面隐藏不主动暂停、静音、暂停/恢复和刷新恢复。
所有短播报逐项映射到真实非静音 WAV，并校验 PCM 秒长；连续阶段音轨逐项覆盖计划并校验语音、提示音和间隔边界。
GitHub Actions 的 `验证` 工作流运行同一测试命令，不承担部署。
本次验证也覆盖手动日期补记、取消和本地覆盖值持久化。

## 浏览器验收

只使用 ego-browser 的一个自有任务空间，通过 `file://` 或同一 Pages 项目的分支预览测试。
不启动本地服务器，不使用其他浏览器自动化栈。

- `index.html?debugMs=100`：1 秒按 100 毫秒执行，约 143 秒计时加四次人工等待；关闭全部声音，仅用视觉计时和独立测试存储。
- `index.html?test=1`：保持标准秒长、中文语音与提示音，但所有进度和打卡仍写测试存储。
- 无参数：正式时长与正式本地数据；自动验收仅检查默认配置，不启动会产生正式记录的测试会话。

测试存储前缀为 `rehab-timer:test:v1:<unit-ms>`，新计划在此后追加 `:joint`；刷新可保留各自的测试打卡，绝不混入正式数据。
不要把加速段当作语音效果测试；加速后的 5 秒短休无法容纳正常中文播报。
`window.__rehabTimer` 仅提供状态、计划与有界诊断事件，没有跳项或强制完成接口。

完整浏览器验收还应确认两个标签、五节顺序、新计划每节结束后的 60 秒休息以及第五节两次点完成。
切换标签时核对进度清除、日历与日期编辑互不显示另一套记录。
其余原计划验收应依次确认：

1. 全部五项走完，四个项间边界经过等待仍不自动开始。
2. 组休点击「跳过休息」只进入当前项第二组，工作/短休无跳过按钮。
3. 第五项四轮共八段，自动交替、连续零点，无额外休息。
4. 完成后刷新仍有一条测试记录，正式存储内容不变。
5. 部分训练暂停、刷新恢复、明确继续、确认结束，不新增打卡或删除历史。
6. 实时测试检查初始 30 秒、15 秒工作、5 秒短休及连续音轨中的语音/提示音交接，记录资源响应、playing/ended、播放位置和边界延迟，单独说明是否真机与人耳验证。
7. 在桌面标签页切换或最小化后，确认连续音轨的 currentTime 和媒体播放状态仍前进；自动化无法设置 document.hidden 时，记录该缺口，并以代码检查和本地 Chromium 播放检查替代，不声称已完成手机锁屏验收。
8. 桌面和手机同轮检查完整长动作名、五点、焦点、对比、触控、翻月和 reduced-motion；批量修正后最多一次视觉确认。

私有证据放在当前任务的私有目录，不提交真实健康历史或个人临床记录。

## 现有 Cloudflare Pages 发布

已通过现有 Wrangler 查询确认项目名 `rehab-timer`，域名 `rehab-timer.pages.dev`，`Git Provider: No`。
这是已有项目的直接上传机制，不是推送 Git 后自动部署，也没有仓库部署工作流。
不新建项目、账户或发布服务。

只上传页面和带许可的声音目录，不上传 `.git`、测试或私有证据：

```sh
mkdir -p .publish
cp index.html .publish/index.html
cp -R audio .publish/audio
# 分支预览，绝不以预览命令覆盖生产分支：
wrangler pages deploy .publish --project-name rehab-timer --branch <当前PR分支>
```

项目使用 GitHub PR；在 PR 合并后，由有权限的发布者从精确合并 SHA 提取 `index.html` 与 `audio/`，通过同一项目既有直接上传入口发布。
合并本身不表示线上已经更新。
发布后必须在 <https://rehab-timer.pages.dev/> 重新验证五点、标准时长与隔离测试流程；部署前不声称生产验收通过。
本次后台能力新增 `audio/stage-1.mp3` 到 `audio/stage-5.mp3`，必须与页面一同发布。
