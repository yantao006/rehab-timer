# 康复训练计时器

两套固定训练计划，共享 Cloudflare D1 历史，不区分使用者。
正式入口：

https://train.yantao006.com/

https://rehab-timer.pages.dev/

训练剂量以 [PRODUCT.md](PRODUCT.md) 为准，视觉规则见 [DESIGN.md](DESIGN.md)，同步协议见 [docs/sync-api.md](docs/sync-api.md)。

## 使用

- 首页选择计划并开始，或者查看保留的暂停进度。
- 训练时底部固定暂停、继续、完成和结束操作。
- 返回首页或切换计划先暂停并保留进度，不自动开始另一套训练。
- 原计划前四项为 15 秒训练 / 5 秒短休，6 次 × 2 组，组休 60 秒可跳过；第五项踮脚 / 拉伸各 30 秒、4 轮，前三轮各在拉伸后休息 30 秒，可跳过轮间休息，第四轮直接完成。
- 下肢计划前四项保留同样剂量，每节末再休息 60 秒且不能跳过；第五项每组 8 到 10 次、不计时，共 2 组。
- 两套计划首次准备 30 秒可跳过，每项之后必须手动开始下一项。
- 下肢第五项完成第一组后停在「下一组就位」，明确开始第二组后才能完成，连点不会跳过一组。
- 结束需要确认，不产生完整记录，也不删除历史。
- 「记录」按当前计划显示月历、周次数和当天每条完成记录，可明确补记一次或撤销某一条。
- 完成页面区分训练已完成、本设备已保留和云端已同步。

## 云端共享和本地恢复

首次使用输入同一共享口令，之后通过安全 Cookie 访问同源 API。
没有个人账号、用户表或按人区分的历史。
正式环境与分支预览使用不同数据库、口令及签名密钥。

D1 是共享记录的权威来源，本地仅保存缓存、恢复快照和待同步操作。
云写入按操作 ID 幂等；完成记录与会话终态在同一事务保存。
本地待同步完成独立于当前进度，返回首页、结束或重开不会抹掉待同步完成。
计时不等待网络，每秒只更新本地快照，约 10 秒合并一次云进度，暂停和阶段边界立即排队。
没有网络或尚未解锁时不新建云端训练，已保留的训练可以继续，联网解锁后重试。
清除网站数据仍可能丢掉尚未上传的操作，必须先确认「已同步」。

不同设备的新训练各有独立会话 ID。
恢复另一设备的训练需要明确「接管」，新设备取得写入权，旧设备的过期写入会产生冲突。
冲突不会静默覆盖；可以采用云端状态，或者把本地已经完成的训练另存为独立会话。
恢复后只停在暂停或就位状态，不计算离线期间经过的时间。

完成日使用完成时的本地日历日期，并保留完成时间与设备时区。
跨午夜取完成日，同日不同训练累计次数，月历仍只标记一天。
撤销针对记录 ID，不建立永久的日期屏蔽，后来同一天的新完成仍会点亮日期。

## 旧数据迁移

在原来使用的浏览器和原来的域名打开新版，进入「共享记录与同步」中的「导入本浏览器的旧记录」。
按「检查旧记录 → 下载备份 → 确认导入」执行。
旧浏览器数据不能由服务器自动读取；其他设备也需要在各自原来源运行迁移。
两个正式域名虽然连接同一 D1，但浏览器的旧本地存储互不共享。

迁移直接扫描原始键，不使用旧版已经被日期覆盖过滤的历史投影：

- 原计划 `rehab-timer:v1:progress`、`:done:<id>`、`:date:<date>`。
- 下肢计划 `rehab-timer:v1:joint:progress`、`:done:<id>`、`:date:<date>`。
- 排除所有测试前缀，损坏内容不上传并在预览中报告。
- 原始数据和下载备份保留，重复导入不重复增加次数。
- 旧 `false` 只撤销本批新导入的相关记录，不撤销云端已有记录，也不影响未来完成。
- 旧 `true` 在当天没有有效完成记录时转换成一条稳定标识的补记。
- 未完成进度转成暂停；已完成但未写历史的终态进度可修复缺失记录。
- 原计划新增轮间休息后，旧进度按相同动作映射到新排程，保留剩余时间；旧完成记录不会因为新增休息变成未完成。
- 每次最多 500 条历史、500 个日期编辑和两套进度，超限明确报告，不截断或静默部分导入。

## 源码和构建

需要 Node.js 22.13 或更新版本；CI 使用 Node.js 24。
业务运行不依赖前端框架或第三方运行时包。

| 路径 | 职责 |
| --- | --- |
| `src/core.js` | 固定训练计划、状态机和媒体适配器 |
| `src/app.js` | 页面、连续音轨控制、交互 |
| `src/repository.js` | 本地恢复、待同步操作、云接口和旧数据迁移 |
| `src/template.html`、`src/styles.css` | 页面结构和样式 |
| `functions/` | Cloudflare Pages Functions API |
| `migrations/` | D1 schema 迁移 |
| `audio/` | 随站固定语音、提示音、连续阶段音轨 |
| `index.html` | 构建生成文件，不手工修改 |

```sh
npm ci
npm run build
npm run validate
npm run build:publish
```

构建把源码内联到单个页面，因此仍可用 `file://` 检查 UI。
发布目录 `.publish/` 只包含生成页面、音频和仅匹配 `/api/*` 的路由配置。
Functions 由 Wrangler 从 `functions/` 编译上传，不复制测试、私有数据或源码目录到静态站。
Wrangler 固定在项目依赖和 lockfile 中。
`npm run validate` 检查生成文件一致性、全部测试与 diff 空白错误，不需要安装 Wrangler 才能运行。

## 自动测试和浏览器验收

```sh
npm run validate
```

测试执行真实训练核心、页面控制器、持久化层和 API handler。
API 与端到端协议集成使用 Node 原生 SQLite，包含实际事务回滚、并发比较更新、响应丢失、离线补传、接管冲突和 500 条迁移边界。
固定规则验证原计划 104 段、1520 秒、三次可跳过轮休及四次人工项间等待，下肢 99 段、全部组休和节休及手工两组。
媒体测试验证首次同步手势播放、连续阶段音轨、暂停恢复及资源一致性。

所有浏览器操作只使用 ego-browser 的一个隔离任务空间。
通过 `file://` 或现有 Pages 项目分支预览验收，不启动本地服务器。

| 入口 | 行为 |
| --- | --- |
| `?debugMs=100` | 100 毫秒代表 1 秒，无声音，独立本地测试存储，不请求 API |
| `?test=1` | 标准秒长与音频，独立本地测试存储，不请求 API |
| `file://` | 本地隔离预览，不读正式历史、不发 API |
| 分支预览无参数 | 标准训练规则，连接预览 D1，用合成数据验证云同步 |
| 正式域名无参数 | 正式 D1，自动验收不制造训练历史 |

`window.__rehabTimer` 只读暴露配置、状态、计划及有界事件，没有跳项或强制完成接口。
旧测试前缀不迁移，新的测试恢复数据位于独立 `rehab-timer:test:v2:` 命名空间。
测试正式 API 时必须使用独立预览数据库，不能把加速记录写入正式历史。

浏览器验收包含手机及桌面布局、完整动作名、底部操作、键盘焦点、计划切换、刷新恢复、逐条撤销与同日新完成、旧键备份导入、离线重试和跨设备接管。
真实解码事件仅证明媒体管线运行，不能证明扬声器可听或手机锁屏兼容。

## 音频和计时边界

同一个 HTMLAudioElement 承载全部语音和提示音。
标准训练以连续阶段音轨播放位置推进，保留语音与动作零点；加速或音频降级计时使用绝对单调时钟边界，不以回调次数累计。
恢复或跳过休息需要非零定位时，先在手势内播放短提示，再从完整加载到内存的阶段音轨定位。
只有确认媒体到达目标位置后才推进训练，定位回零、倒退或异常跳跃都保留最近确认的快照并暂停。
音轨加载最多等待 12 秒，播放连续 8 秒无进展会保守暂停，不把等待算成训练完成。
首次开始、继续、试听都在用户手势内调用 `play()`，不得先等待网络或数据库。
原有素材、许可和重生成方法见 [audio/README.md](audio/README.md)。

桌面隐藏标签通常可继续播放，媒体中断后保守暂停；项间始终等待明确操作。
手机锁屏、系统省电、静音开关、音量及蓝牙路由由系统控制，不能保证 iOS 锁屏持续播放。
实际 iPhone 播放与人耳验收需在目标设备进行，不把自动化结果写成已通过真机听音。

## Cloudflare 部署

继续使用已有直接上传 Pages 项目 `rehab-timer`，不使用 Git 自动部署。
`wrangler.jsonc` 保存两套数据库绑定和 APP_ENV；口令与签名密钥仅放 Pages 环境 secret，不进 Git 或前端。
服务器缺少任一配置时返回 503，不开放匿名数据读写。

首次部署在相应环境配置 `SHARED_PASSPHRASE` 和不少于 32 字符的 `SESSION_SECRET`，再应用 schema。
本地私有密钥文件放在被忽略的 `.private/`，不要上传或在日志输出。

```sh
npx wrangler d1 migrations apply rehab-timer-preview --remote --env preview
npm run build:publish
npx wrangler pages deploy .publish --project-name rehab-timer --branch codex/rehab-shared-d1
```

生产发布遵循 GitHub PR 流程，验证并合并后从精确合并 SHA 构建。
先应用正式数据库迁移，再按现有生产分支发布，不能把预览数据库绑定带入正式环境。

```sh
npx wrangler d1 migrations apply rehab-timer-production --remote
npm run build:publish
npx wrangler pages deploy .publish --project-name rehab-timer --branch main
```

PR 合并不等于部署完成，必须分别核对 Pages 部署 SHA、正式域名页面和 API。
生产上线后只读核验或使用 `?test=1`，不能在正式 D1 写入合成训练。
schema 为增量创建，回滚页面时不要删除数据库或撤销原始记录。
历史仍在 D1，临时回滚到旧纯本地页面不会继续显示云端新增记录，应优先向前修复。
